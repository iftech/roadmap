  • ift:2026q4-ir-vulma:security-incidents

    • Keycloak account takeover (2026-11-05) via CVE-2026-18963 (GHSA-4gv3-mc9p-5wqc, unauthenticated reset-credentials bypass). We ran 26.6.2; the fix had shipped in 26.7.2 on 2026-10-19. Worked it with jakubgs, tracked in infra-office#123:
    • Containment: Keycloak and the oauth proxies shut down; prod BI DB credentials rotated; Keycloak DB to be restored from the pre-attack backup
    • Impact (assessment):
      • Vault and Consul held behind their second auth layer; Vault access was verified
    • Patched:
      • Keycloak 26.6.2 → 26.8.2 (infra-role-keycloak#5, merged 2026-11-07)
      • oauth2-proxy 7.15.2 → 7.15.6 (infra-role-oauth-proxy#11)
      • Uptime Kuma 2.2.1 → 2.5.9 (infra-hq#326)
    • Postmortem draft: infra-docs#56
    • Gap found: admin-events logging was off in all three realms (logos-co, master, status-test). Admin-side changes can only be found by diffing against a snapshot

  • ift:2026q4-ir-vulma:vulnerability-management

    • SSHole (CVE-2026-123158, CVSS 8.1): OpenSSH password-auth bypass on musl builds without PAM
      • A password of 257–1,024 bytes logs into any account that has no password
      • Affected: Alpine openssh-server, plus OpenWrt, Buildroot and Yocto. Not affected: glibc distros and Dropbear
      • Exploit code appeared ~4 h after the 10.6p2 release (2026-11-05); in-the-wild root on a honeypot came within 9 h
      • Assessed our exposure
    • Linux kernel TCP/MPTCP use-after-free now has an ID: CVE-2026-98432 (CVSS 9.8)
      • status-go #8027 (merged 2026-11-02) sets godebug multipathtcp=0, so no status-go binary opens MPTCP listeners (go-waku libp2p host on 0.0.0.0, torrent client, pairing/media/connector servers)
      • That is defense in depth only. Fixed kernels: 6.1.190 / 6.6.159 / 6.12.113 / 6.18.56 / 5.15.223 / 5.10.272
    • BLS point-at-infinity fix vendored: nimbus-eth2 #9410 (merged 2026-11-04), nimbus-eth1 #5101 (merged 2026-11-05)
